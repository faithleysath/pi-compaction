# Benchmark

```bash
bun run bench         # 打印表格
bun run bench:update  # 更新 bench/results.json
bun run bench:check   # 和基线逐字节比较，提交前 / CI 跑
```

用真实 handler 跑固定的合成会话，量摘要大小。不调模型、不联网，也不读写你真实的
`~/.pi/agent/pi-compaction.json`（脚本把 `PI_CODING_AGENT_DIR` 指到临时目录）。

## 为什么有这组数据

README 里的 6 轮摘要大小和「能压多少次」都是这个脚本跑出来的。这些数字以前是手工测的，
改格式说明或折叠标记之后没人重跑，数字就和代码对不上了。现在固定会话、固定切点、无随机数，
改完重跑一遍，把输出贴回文档。

## 三组 workload

- **短轮次**：1 轮 = 1 个 turn（1 条用户消息 + 1 条助手正文 + 3 个工具调用 + 3 条结果
  + 1 条助手收尾），压 6 轮。用来看摘要随轮次怎么长。
- **paseo**：1 轮 = 3 条 `agent-notification` 信封（各 1.5k 字符正文）+ 1 条 `agent-message`
  派活回显 + 1 次 `mcp__paseo__send_agent_prompt` 调用，压 4 轮。三封通知的标题固定，
  所以能测到跨轮次的 `×N` 合并 —— 心跳场景就是这个形状（合并按「标题 + 短 agent id」分组，
  所以 id 固定不随轮次变）。
- **完整周期**：1 轮 = 55 个 turn（每 turn 1 次工具调用），接近真实会话两次压缩之间的量。
  压 2 轮拿到每轮增量，再外推 1M 窗口能压多少次。

固定参数：工具参数截断 300、结果头 200 / 尾 100；文本内容固定，无随机数。
切点固定在下一轮开头，本轮正文 = 一个完整轮次。

## 当前结果

### 短轮次：压 6 轮

| 轮次 | `collapseOldTools: false` | `true` | 折叠掉 |
|---|---|---|---|
| 1 | 2,436 | 2,436 | 0.0% |
| 2 | 4,395 | 2,783 | 36.7% |
| 3 | 6,360 | 3,135 | 50.7% |
| 4 | 8,325 | 3,484 | 58.2% |
| 5 | 10,290 | 3,833 | 62.8% |
| 6 | 12,255 | 4,182 | 65.9% |

6 轮后：12,255 → 4,182 字符，折叠掉 65.9%。

### paseo：信封占 user 侧 90%

| 轮次 | `paseo.collapseEnvelopes: false` | `true` | 折叠行数 |
|---|---|---|---|
| 1 | 6,771 | 6,771 | 0 |
| 2 | 12,922 | 7,406 | 4 |
| 3 | 19,075 | 7,683 | 4 |
| 4 | 25,228 | 7,948 | 4 |

4 轮后：25,228 → 7,948 字符，省 68.5%。折叠行数不随轮次增长（3 条通知 + 1 条派活合并成 4 行），
不折的话每轮 +6,150 字符。

### 完整周期：1M 窗口能压多少次

摘要预算：`(1,000,000 − 16,384 − 20,000) × 4 = 3,854,464` 字符（按 pi 的 4 字符/token 估算）。

| `collapseOldTools` | 1 轮后 | 2 轮后 | 每轮增量 | 压缩次数 | 对话 turn 数 |
|---|---|---|---|---|---|
| `false` | 45,873 | 91,404 | 45,531 | 84 | 4,620 |
| `true` | 45,873 | 65,208 | 19,335 | 197 | 10,835 |

折叠后能多压 **2.3×**。

## 怎么读

- **字符不是 token。** pi 估算约 4 字符/token，这里只比较相对大小。
- **「压缩次数」是外推。** 按实测的每轮增量线性加到预算上限，不是真的跑满 1M 窗口。
  真实会话的每轮内容会变，绝对次数只能当量级看。
- **绝对大小取决于每轮内容。** 文本越长、工具内容越少，折叠省得越少；换 workload 要同时
  改这里的说明和 README 里的表。
- **改这些之后必须重跑**：`FORMAT_NOTE`、`TAIL_NOTE`、折叠标记、三个截断默认值。
  它们每个字符都会进入每一份摘要，差几十个字符就能让表格里的数全变。

## 输出

脚本同时打印一段 `<!-- bench-json … -->`；`--write` 会把它原样写进 `bench/results.json`，
`--check` 逐字节比较。跑两次的输出应当完全一致（没有随机数、没有时间戳）。

改了格式说明、尾注、折叠标记或截断默认值，`bench:check` 会失败。这时：

1. `bun run bench:update` 更新基线
2. 把新表格贴回 README 和 `docs/design.md`
3. 两边一起提交
